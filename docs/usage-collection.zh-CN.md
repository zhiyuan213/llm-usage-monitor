# 加购包与超额费用结算

规格：Core/Pro 活跃订阅可购买每包 100,000 units / USD 8（含税），仅当前账期有效，不自动续购。加购仅覆盖后续新增用量，不追溯抵扣已产生的超额费。付款以 Paddle 验签回调或经认证的服务端对账为准，前端完成事件不发放额度。

## 数据与收费

- 每包单独记录购买、已消耗、退款及对应账期；接入在工作空间锁内依次消费基础额度、可用加购包、已授权超额。更新已有对象不收费。
- `overage_units` 只统计用户授权后实际预留的超额对象。加购或退款不会重新定价历史用量。补偿同时释放对应包或超额计数；已结算账期禁止直接补偿，需人工调整原账单。
- 账期变更、取消或到期扫描固定结算金额；数据库唯一约束保证每账期只生成一笔超额结算。金额沿用现有阶梯价，向下取整到美分，不超过授权金额；不足一美分免收。
- 活跃订阅通过 Paddle `POST /subscriptions/{id}/charge` 添加立即收取的一次性费用。取消或逾期订阅改为一次性收银台付款，不继续向已取消订阅的保存方式强行扣款。
- 外部写入前持久化处理状态；响应丢失或超时保持 `unknown`，不自动重新提交扣款。唯一价格说明标识与交易自定义数据用于对账；金额、币种、数量和非周期价格均核对。
- 支付失败或尚未确认的旧超额账单阻止继续使用自动超额，基础及已付款加购额度仍可使用。Paddle 后续成功通知可解除限制。
- 任意获批加购退款撤回整包尚可用资格，保留该包消费记录，避免已用额度变为未经授权的新收费。跨账期或订阅取消后才完成的加购标为 `refund_required`，不错误发到新账期；需要运营在 Paddle 审核并退款。

## 启用与运维

默认 `USAGE_COLLECTION_ENABLED=false`，API 与 Worker 必须同时配置为 true，并重新创建服务。沿用后端 Paddle API 密钥的 Transactions Read/Write、Subscriptions Read/Write 权限；无需在前端放后端密钥。以已有订阅产品创建非目录一次性价格，8美元加购规格只能由服务端决定。

首次启用前完成沙箱：加购成功/失败/重复回调、实际一次性扣款、丢失响应对账、账期到期及退款。正式环境仍需商户资格和运营确认。`unknown` 不等于失败，不得仅把数据库状态改回 ready 重扣；先在 Paddle 按交易或唯一说明核对。

`GET /api/billing/usage-charges` 仅返回当前工作空间的状态、剩余额度和最多100笔记录。`POST /api/billing/addons` 需要现有会话、CSRF及 `consent=true`。并发或重复请求复用未完成订单。距离账期结束不足15分钟不能新建加购，避免付款跨期。

对账每轮最多5个意图，每个最多5页，每次请求15秒超时，轮转检查；查询不到继续保留未确认，不能记为支付成功。

参考：[Paddle一次性订阅收费](https://developer.paddle.com/api-reference/subscriptions/create-subscription-charge/)、[交易列表](https://developer.paddle.com/api-reference/transactions/list-transactions/)。
