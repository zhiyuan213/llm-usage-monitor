# 预算提醒与失败、慢调用分析

实现日期：2026-10-25。项目导航新增“预算提醒”与“失败与慢调用”。两项基础功能面向 Core / Pro，Free 显示升级入口；Free 仍能关闭以前开启的预算提醒。

## 预算提醒

- 每个项目独立设置美元月预算，按 UTC 自然月统计已上报生成类 Observation 的模型估算费用，不加总 Trace 费用，不包含 MeterTrail 订阅费。
- 邮件默认关闭，仅用户主动开启后发送到其已验证账号邮箱。Core 使用 80% 提前提醒线，Pro 可设置 50%～95%；达到 100% 时提示已达预算。
- 可选择开启月末费用预测提醒。预测要求月初已过至少 3 天、至少 20 次模型调用、全部调用价格已知，且整个期间仍在保留期内。计算公式为“已知模型费用 × 本月秒数 ÷ 本月已过去秒数”，不是未来流量预测。
- 缺失价格不补零，不据此预测。若已知小计本身已达提醒线，仍可发实际费用提醒，并说明覆盖率。
- Worker 每分钟挑选最多 20 个到期项目，每个项目检查后间隔约 5 分钟。停机恢复只检查当前自然月，不补发过去月份。保存设置会让项目在下一轮尽快检查。
- 同一次检查优先发送已达预算，其次接近预算，再其次预测超预算。同一项目、同一 UTC 月份、同一提醒类型最多生成一次；修改预算不重置次数。生成快照、邮件入队与更新检查时间在同一事务内，失败回滚后可重试。
- 使用现有加密邮件 outbox。发送前重新检查订阅、项目/账号是否删除、邮箱是否改变及是否仍为付费套餐；关闭提醒取消未发邮件。发送中的邮件可能仍到达，邮件服务接收不保证收件箱送达，模糊 SMTP 失败可能重复投递。
- 提醒不会限制用户模型调用、停止数据接入、扣款或改变现有额度策略。列表金额保留生成提醒时的预算与费用，后续更正不会重算旧记录。
- 提醒历史最多保留 90 天，同时受套餐保留期限制；账号或项目删除后清理终态提醒快照。

## 失败与慢调用

- 应用请求（Trace）与模型调用（生成类 Observation）分开选择，不能将二者相加作为请求数。
- 最近 24 小时 / 7 天 / 14 天，按每条调用自己的开始时间统计，起点包含、终点不包含，只分析已上报且仍保留的最新版本。
- 提供调用数、失败率、取消数、慢调用数、耗时覆盖率以及 P50 / P95 / P99。失败率分母是该类全部调用，慢调用率分母是有耗时的调用。取消不等于失败，缺失耗时不按零处理。
- Core 慢调用阈值固定为 3 秒，Pro 可设置 500～600,000 毫秒。等于阈值也算慢调用，慢调用和失败可以重叠。
- 功能/模型分组展示最多 50 组，按失败或慢调用数排序；错误说明按应用提供的原文合并，最多 50 组。具体失败/慢调用完整分页，每页 5/10/50/100，默认 5；慢调用按耗时倒序。
- 模型分组建议选择模型调用；未上报的分组维度归入未归类。具体调用可跳转到对应 Trace。错误说明以纯文本展示，不执行 HTML，也不将它当作系统推断的根因。
- 样本少于 20 条时显示提示。分位数描述所选数据，不能据此推断服务保证或未上报请求的表现。

## 权限、运行和升级

API 复用登录会话、CSRF、项目所有权、套餐和速率校验；Pro 自定义规则由后端校验，不能只依赖按钮禁用。查询参数采用白名单和绑定参数，分析走独立只读连接池、一致性快照及 15 秒事务超时。

迁移为 `V16__budget_reminders.sql`。更新 API、Worker、前端后生效；既有小时级告警规则、周报、上报和计费协议保持原样。预算提醒独立调度，不与上报消费共用调度线程。

## 手动周报发送补充

周报页的“发送周报”位于“预览上周周报”右侧。需先开启周报，使用已保存时区，立即生成上一个完整自然周并入队，不移动下次定时发送时间。同周已有记录时返回该提示，不重复生成邮件。该入口与自动任务共用唯一约束、权限及发信资格检查。
